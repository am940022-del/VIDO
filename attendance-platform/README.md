# منصة رصد الحضور (الغياب، التأخير، الهروب)

منصة ويب لرصد غياب الطلاب وتأخرهم وهروبهم في المدرسة، بواجهة عربية تعمل على الجوال والحاسب.

## الفكرة

| الدور | الدخول | ما يفعله |
|---|---|---|
| **مدير المدرسة** | بريد + كلمة مرور | يسجّل المدرسة، يرفع قوائم الطلاب والمعلمين، يحدد الحصص، يرى الإحصائيات ويصدّر التقارير |
| **المعلم** | رابط خاص بالمدرسة، **بدون تسجيل دخول** | يختار الصف ← الشعبة والحصة ← يضغط على الطالب ويحدد: غياب / تأخير / هروب |

## التشغيل

```bash
cd attendance-platform
npm install
npm start          # http://localhost:3000
npm test           # اختبارات الـ API والعزل بين المدارس
```

متغيرات البيئة الاختيارية:

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `3000` | منفذ الخادم |
| `DATA_DIR` | `./data` | مكان ملف قاعدة البيانات SQLite |
| `SCHOOL_TZ` | `Asia/Riyadh` | المنطقة الزمنية لتحديد تاريخ "اليوم" |
| `TEACHER_RATE_LIMIT` | `1500` | أقصى عدد طلبات للمعلمين في الدقيقة لكل مدرسة وعنوان |
| `BACKUP_INTERVAL_HOURS` | `24` | النسخ الاحتياطي التلقائي كل كم ساعة (`0` لتعطيله) |
| `BACKUP_KEEP` | `14` | عدد النسخ الاحتياطية المحفوظة |
| `COOKIE_SECURE` | `true` في الإنتاج | اجعله `false` فقط للتجربة بدون HTTPS |
| `NODE_ENV` | — | اضبطه على `production` خلف HTTPS لتفعيل الكوكي الآمن |

## النشر على خادم

### على نفس خادم إنتماء ودفتر (بدون تكلفة إضافية)

سكربت التثبيت يكتشف إنتماء في `/opt/athar` تلقائياً، ويعمل بنفس طريقة دفتر:
- لا تشغّل المنصة Caddy خاصاً بها؛ Caddy إنتماء يستقبل زوار المنصات الثلاث.
- تنضم المنصة لشبكة `edge` المشتركة باسم `attendance-app`.
- يضيف المنصة إلى `/opt/athar/deploy/docker-compose.override.yml` **مع الإبقاء على كل ما أضافته المنصات الأخرى (دفتر، PILL…)**: ملف Caddy الرئيسي الحالي يُستورد كما هو ثم يُضاف موقع الحضور. يحتفظ بنسخة من الملف السابق، ويتراجع تلقائياً إن فشل إعداد Caddy.
- كود إنتماء ودفتر لا يتغير.

**1. سجل DNS**: أضف سجل `A` للنطاق الفرعي (مثل `attendance.<نطاق إنتماء>`) يشير إلى عنوان IP الخادم نفسه.

**2. على الخادم:**
```bash
ssh root@<IP>
git clone -b main https://github.com/am940022-del/VIDO.git /opt/vido
cd /opt/vido/attendance-platform && sudo bash deploy/install.sh
```
اضغط Enter لقبول القيم المقترحة (النطاق `attendance.<نطاق إنتماء>`، المنطقة الزمنية `Asia/Muscat`، رمز الدولة `968`).

**3.** افتح `https://attendance.<نطاق إنتماء>` وسجّل المدرسة الأولى.

| المهمة | الأمر (من `/opt/vido/attendance-platform`) |
|---|---|
| نشر نسخة جديدة | `sudo bash deploy/update.sh` (يأخذ نسخة احتياطية أولاً) |
| حالة المنصة | `docker compose ps` |
| السجلات | `docker compose logs -f app` |

**مهم:** إن أعدت تشغيل سكربت تثبيت **دفتر أو PILL** فقد يعيد كتابة ملف Caddy المشترك، فأعد بعده تشغيل `sudo bash deploy/install.sh` لمنصة الحضور (دقيقة واحدة، والبيانات محفوظة). أما `update.sh` لدفتر أو إنتماء فلا يؤثر.


### الطريقة الموصى بها: خادم VPS + Docker (HTTPS تلقائي)

يكفي خادم صغير (1 معالج، 1 جيجابايت ذاكرة) من أي مزود (Hetzner، DigitalOcean، AWS Lightsail، أو مزود محلي)، ويخدم عشرات المدارس.

1. **النطاق**: أنشئ سجل DNS من نوع `A` لنطاقك (مثلاً `attendance.example.com`) يشير إلى عنوان IP الخادم.
2. **ثبّت Docker** على الخادم (Ubuntu):
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
3. **انسخ المشروع وشغّله**:
   ```bash
   git clone <رابط المستودع> && cd <المستودع>/attendance-platform
   cp .env.example .env
   nano .env            # ضع نطاقك في DOMAIN
   docker compose up -d --build
   ```
4. افتح `https://نطاقك` — الشهادة تُصدر تلقائياً من Let's Encrypt عبر Caddy خلال دقيقة.
5. افتح المنفذين 80 و443 فقط في جدار الحماية:
   ```bash
   ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable
   ```

**التحديث لاحقاً:**
```bash
git pull && docker compose up -d --build
```

**النسخ الاحتياطي:**
- تلقائي كل 24 ساعة داخل وحدة التخزين (`/data/backups`) مع الاحتفاظ بآخر 14 نسخة.
- نسخة فورية إلى الخادم: `./deploy/backup-now.sh` (تُحفظ في `backups/`). يُنصح بنسخ هذا المجلد دورياً خارج الخادم.
- الاستعادة: `./deploy/restore.sh backups/attendance-XXXX.db`

**السجلات والحالة:** `docker compose logs -f app` — وفحص الصحة على `/healthz`.

### بديل: منصات الاستضافة المُدارة (Render / Railway / Fly.io)

المشروع يحتوي `Dockerfile` جاهزاً. الشروط:
- **قرص دائم (Persistent Disk/Volume)** مركّب على `/data` — بدونه تُحذف البيانات عند كل نشر.
- نسخة واحدة فقط من التطبيق (SQLite لا يدعم تشغيل عدة نسخ على نفس الملف).
- متغيرات البيئة: `NODE_ENV=production` و`SCHOOL_TZ=Asia/Riyadh`، والمنصة توفر HTTPS تلقائياً.
- مسار فحص الصحة: `/healthz`.

### ملاحظات أمان للإنتاج
- لا تشغّل المنصة بدون HTTPS: كوكي الدخول آمن (`Secure`) ولن يعمل على `http`.
  للتجربة فقط على عنوان IP بدون شهادة: `COOKIE_SECURE=false`.
- التطبيق يعمل بمستخدم غير root داخل الحاوية، ومنفذه غير مكشوف مباشرة (Caddy فقط).
- ملف `.env` لا يُرفع إلى Git.

## تعديل الصفوف بعد رفع القوائم

من تبويب **الطلاب والصفوف**:

| الحالة | كيف | ماذا يحدث |
|---|---|---|
| **نقل طالب لشعبة أخرى** | «تعديل / نقل» ← اختر الشعبة، أو حدد عدة طلاب ← «نقل» | يظهر في قائمة الشعبة الجديدة فوراً؛ سجلاته السابقة تبقى باسم شعبته القديمة |
| **منقطع** | «تعديل / نقل» ← الحالة: منقطع، أو تحديد جماعي ← «منقطع» | يختفي من قوائم المعلمين ولا يمكن رصده، وتبقى سجلاته وكشوفه |
| **منتقل من المدرسة** | بنفس الطريقة ← «منتقل من المدرسة» | مثل المنقطع، مع تمييزه في القوائم |
| **عودة طالب** | «إعادة تفعيل» | يعود لقوائم المعلمين |
| **إعادة تسمية أو دمج شعبتين** | «تعديل» بجانب الشعبة | إن كتبت اسم شعبة موجودة تُدمج الشعبتان |

لكل تغيير تاريخ وسبب، ويُحفظ في **سجل تغييرات الطالب**.

**تحديث القائمة من ملف جديد** (الطريقة الأسهل في بداية الفصل أو بعد تعديلات كثيرة): ارفع ملف الطلاب الكامل باختيار «تحديث القائمة»، فتعرض المنصة **معاينة قبل التطبيق**:
- من تغيرت شعبته ← يُنقل،
- الطلاب الجدد ← يُضافون،
- المنقطعون/المنتقلون الموجودون في الملف ← يُعاد تفعيلهم،
- من ليس في الملف ← تختار: إبقاؤهم، أو اعتبارهم منتقلين، أو منقطعين.

المطابقة تتم برقم الطالب إن وُجد، وإلا بالاسم. إن تكرر اسم في أكثر من شعبة بدون رقم طالب يُتجاهل ويظهر في المعاينة لتصحيحه.

## صيغة الصفوف والشعب

- الصف رقم أو نص: `11` أو `الصف 11` أو `١١` كلها تُعامل كـ **الصف 11**، و«الأول المتوسط» يبقى كما هو.
- الشعبة: `1` أو `الشعبة 1` أو `١`.
- يمكن أيضاً وضع الصف والشعبة في عمود واحد: `11/1` أو `11-2`.
- الترتيب طبيعي: الصف 9 ثم 10 ثم 11، والشعبة 2 قبل 10.

## خطوات الاستخدام

1. افتح الصفحة الرئيسية وسجّل المدرسة (اسم المدرسة، اسم المدير، البريد، كلمة المرور).
2. من تبويب **الطلاب والصفوف** ارفع ملف Excel/CSV بالأعمدة: `اسم الطالب، الصف، الشعبة` (واختيارياً: `رقم الطالب، جوال ولي الأمر`). تفصل المنصة الطلاب تلقائياً على الصفوف والشعب. يوجد قالب جاهز للتحميل.
3. من تبويب **المعلمون** ارفع ملف بعمود `اسم المعلم` (واختيارياً `المادة، الجوال`) أو أضفهم يدوياً.
4. من تبويب **الحصص** حدد عدد الحصص (افتراضياً 7) وأوقاتها اختيارياً — عند تحديد الأوقات تُختار الحصة الحالية تلقائياً للمعلم.
5. انسخ **رابط المعلمين** وأرسله لهم.
6. تابع **الإحصائيات**: الإجمالي، حسب الصف والشعبة، حسب الحصة، الأكثر غياباً/تأخراً/هروباً، وملخص لكل طالب.
7. من **السجلات** فلتر حسب التاريخ والصف والشعبة والحالة والاسم، وصدّر إلى **Excel** أو **PDF** (صفحة طباعة ← حفظ كـ PDF).

## سرعة الرصد (أقل من 30 ثانية)

- **ضغطة واحدة لكل طالب**: أزرار «غائب / متأخر / هارب» بجانب كل اسم، والضغط مرة أخرى يلغي. الجميع حاضرون افتراضياً فلا يُرصد إلا المخالف.
- **فتح القائمة مباشرة**: الحصة الحالية تُختار تلقائياً من أوقات الحصص، فيكفي: الصف ← الشعبة ← القائمة.
- **«متابعة آخر صف»**: زر في أول الصفحة يفتح آخر شعبة مباشرة.
- **حفظ مجمّع**: التغييرات تُرسل في طلب واحد بعد أقل من ثانية من آخر ضغطة، وتُحفظ على الجهاز عند انقطاع الإنترنت ثم تُرسل تلقائياً.
- **تحميل فوري**: بيانات المدرسة تُعرض من ذاكرة الجهاز وتُحدّث في الخلفية، مع ضغط gzip للاستجابات.
- في تجربة على الخادم المحلي: 1000 طلب حفظ متزامن نُفذت في حوالي 1.6 ثانية.

## إشعار أولياء الأمور

- **كشف لكل طالب** (PDF للطباعة) و**Excel** لكل طالب، من ملخص الطلاب أو من قائمة الطلاب.
- **كشوف أولياء الأمور**: ملف PDF واحد فيه صفحة مستقلة لكل طالب لديه حالات في الفترة.
- **إرسال عبر واتساب أو SMS**: رسالة جاهزة بالملخص والتفاصيل تُفتح في واتساب على رقم ولي الأمر — بدون أي تكلفة أو اشتراك. يُحوَّل الرقم المحلي (05…) للصيغة الدولية برمز الدولة من الإعدادات (966 افتراضياً).

## حماية البيانات

- كل جدول يحمل `school_id`، وكل استعلام مقيد بمدرسة الجلسة أو رابط المعلمين — لا يمكن لمدرسة رؤية أو تعديل بيانات مدرسة أخرى (مغطى في الاختبارات).
- كلمات المرور مشفرة بـ bcrypt، والجلسة كوكي `httpOnly` و`SameSite=Lax`، مع تحقق من مصدر الطلب.
- رابط المعلمين رمز عشوائي طويل؛ يمكن للمدير **إنشاء رابط جديد** في أي وقت فيتوقف القديم فوراً.
- المعلم يرصد لتاريخ اليوم فقط، ولا يرى إلا أسماء الطلاب (بدون أرقام الجوال).
- تحديد معدل المحاولات لتسجيل الدخول، وترويسات أمان (CSP وغيرها) عبر helmet، وعدم إرسال الرابط في Referer.
